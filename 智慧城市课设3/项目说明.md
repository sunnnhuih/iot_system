# 智慧城市路侧环境监测与智能照明系统

本目录是一个可直接用 Keil MDK 打开的双节点物联网课设工程。A 板负责路侧采集和本地照明控制，B 板负责 LoRa 边缘网关、OLED/蜂鸣器和 ESP-12F Wi-Fi/TCP 服务。手机连接 B 板建立的热点后，可以查看数据并发送控制命令。

快速入口：

- B 板工程：`Dome1-B/Project/CS-LORA.uvprojx`
- A 板 HEX：`Dome1-A/Project/Objects/CS-LORA.hex`
- B 板 HEX：`Dome1-B/Project/Objects/CS-LORA.hex`

## 1. 先确认硬件范围

工程按下列硬件编写：

- 两块 STM32F103C8T6 CS-LORA 开发板（每块板上的 LoRa 模块使用原工程的 USART2）；
- 一个 ESP-12F（用户提供的照片中可见 `3.3V、RST、EN、TXD、RXD、IO0、IO2、GND`）；
- A 板外接 DHT11、烟雾传感器模拟输出、光敏传感器模拟输出、人体红外、继电器/低压灯；
- B 板蜂鸣器和 OLED 使用开发板原有器件或原工程接法。

如果手头实际上只有“两块主板和一个 ESP-12F”，没有上述传感器，程序仍可烧录和观察 OLED/通信，但不能完成真实的温湿度、烟雾、光照、人体和继电器测试。MQ 烟雾模块、光敏模块、PIR 和继电器不是由这份代码凭空产生的，必须有实物或安全的信号模拟电路。

本次只收到 ESP-12F 照片，没有两块 LoRa 开发板排针的正反面高清照片。因此下面使用 STM32 的 MCU 网络名（例如 `PA1`、`PB10`）标线；把杜邦线插到开发板时，请在板上丝印或原理图中找到同名排针，不能根据本文臆造排针的第几个孔。补充开发板照片后，可以再把这些网络名换成具体孔号。

## 2. 系统结构

本项目把前面课设中的两条主线合并：课设 1/LoRa 部分保留 A、B 节点之间的串口透明传输和远程控制；课设 2/Wi-Fi 部分保留 ESP8266 AP、TCP Server 和手机调试工具。新增的环境采集、自动照明和报警逻辑放在这两条链路之上，便于后续写课程设计文档时按“感知层—LoRa 边缘层—Wi-Fi 应用层”展开。

```text
A 板传感器 ──> STM32-A ──USART2/LoRa──> STM32-B ──USART3──> ESP-12F AP/TCP
       │             │                         │                    │
       └── PB2 继电器┘                         ├── OLED/蜂鸣器       └── 手机 TCP 工具
                                              └── 命令经 LoRa 返回 A
```

A 板每 2 秒采集一次数据并发送；B 板收到以 `A,` 开头的帧后更新 OLED、蜂鸣器和手机 TCP 输出。手机命令先由 B 板规范化，再以 `B,CMD=...` 通过 LoRa 发给 A；A 执行后回传 `A,ACK=...`。

## 3. A 板接线（采集节点）

### 3.1 MCU 网络分配

| 功能 | STM32 网络 | 代码/说明 |
|---|---|---|
| DHT11 DATA | `PA12` | `DHT11_Init/Read_TempAndHumidity` |
| 烟雾 AO | `PA1 / ADC1_IN1` | `ADC_Read[0]` |
| 光敏 AO | `PA6 / ADC1_IN6` | `ADC_Read[1]` |
| PIR OUT | `PA0` | `ReadInfrared()`，高电平表示有人 |
| 继电器 IN | `PB2` | 低电平吸合，代码使用开漏输出 |
| LoRa TX/RX | `PA2/PA3 = USART2_TX/RX` | 9600-8-N-1，透明传输 |
| LoRa M0/M1 | `PB5/PB4` | `00` 为正常透传 |
| OLED | `PA5/PA7/PA4/PB0` | SCLK/SDIN/RST/DC，沿用原驱动 |

计划草案曾把继电器写成 `PA2`。这在本板上不能采用：`PA2` 已经是 LoRa 的 `USART2_TX`。本工程统一改为 `PB2`，否则继电器控制会和 LoRa 发送互相抢占同一个 GPIO。接线和代码都以 `PB2` 为准。

### 3.2 逐根线连接

| 外设 | 外设引脚 | 接到 A 板 | 备注 |
|---|---|---|---|
| DHT11 | VCC | 3.3 V | 先确认传感器模块允许 3.3 V |
| DHT11 | GND | A 板 GND | 必须共地 |
| DHT11 | DATA | `PA12` | 裸 DHT11 在 DATA 与 3.3 V 之间加 4.7–10 kΩ 上拉；模块自带上拉则不重复加 |
| 烟雾模块 | AO | `PA1` | 只接模拟 AO，DO 不使用 |
| 烟雾模块 | VCC/GND | 按模块标称电压/ A 板 GND | 若模块用 5 V，AO 可能超过 3.3 V，必须分压或改用 3.3 V 供电；STM32 ADC 绝不能输入 5 V |
| 光敏模块 | AO | `PA6` | DO 不使用；先观察明暗时 ADC 变化方向 |
| 光敏模块 | VCC/GND | 3.3 V / A 板 GND | AO 必须不超过 3.3 V |
| PIR | OUT | `PA0` | 输出必须是 3.3 V 逻辑；若模块 OUT 为 5 V，需分压/电平转换 |
| PIR | VCC/GND | 按模块要求 / A 板 GND | HC-SR501 上电后通常需要几十秒稳定 |
| 继电器模块 | IN | `PB2` | 当前驱动为低有效：`PB2=0` 吸合，`PB2=1` 释放 |
| 继电器模块 | VCC/GND | 按模块要求 / A 板 GND | 课堂演示请只接低压 LED/小灯，不要直接接市电 |

LoRa 模块若已经焊在 CS-LORA 板上，不需要再把 `PA2/PA3/PB4/PB5` 外接出来；若使用裸模块，则按上表交叉连接：STM32 `PA2(TX)` → LoRa `RX`，STM32 `PA3(RX)` ← LoRa `TX`，并连接 3.3 V、GND、M0、M1。板上的 M0/M1 跳线或拨码应保持原工程默认接法，使 MCU 能读到 `M0=0、M1=0` 的透传状态，不能把其中一根长期拉高。

## 4. B 板接线（网关）

### 4.1 LoRa、OLED、蜂鸣器

B 板 LoRa 和 OLED 沿用原工程：LoRa 使用 `PA2/PA3`（USART2）、`PB5/PB4`（M0/M1）；OLED 使用 `PA5/PA7/PA4/PB0`。蜂鸣器信号线为 `PA12`，当前宏定义为高电平响、低电平关，代码只调用 `Beep_Init()`，不会调用会占用 `PB8` 的旧总 GPIO 初始化函数。

### 4.2 ESP-12F 逐针连接

ESP-12F 必须使用稳定的 3.3 V 电源，不能把任何 ESP 针脚接到 5 V。B 板程序中的 USART3 连接如下：

照片背面的 2×4 丝印表可以作为找针脚的方向参考，但插接前仍以你手上转接板的实际丝印为准；不要把模块裸焊盘的排列当成开发板排针编号。

若把照片中的丝印面保持同一朝向，表格从上到下大致为：左列 `3.3V、RST、EN、TXD`，右列 `RXD、IO0、IO2、GND`。实际焊接仍应逐个核对字样。

| ESP-12F（照片丝印） | B 板 STM32 网络 | 方向/作用 |
|---|---|---|
| `3.3V` | 独立稳定 3.3 V | 建议稳压器连续电流至少 500 mA，并在模块旁放 0.1 µF + 100 µF 去耦 |
| `GND` | B 板 GND | 独立电源也必须与 B 板共地 |
| `RXD` | `PB10 / USART3_TX` | B 板发送 → ESP 接收 |
| `TXD` | `PB11 / USART3_RX` | ESP 发送 → B 板接收 |
| `EN`（又称 `CH_PD`） | `PB8` | 程序拉高后模块工作；可另加 10 kΩ 上拉 |
| `RST` | `PB1` | 高电平正常，低脉冲复位；可另加 10 kΩ 上拉 |
| `IO0` | 3.3 V | 正常运行/AT 模式保持高电平 |
| `IO2` | 3.3 V | 正常运行保持高电平 |

烧录 ESP 固件时才按固件工具要求改变 `IO0`；本项目运行时不要把 `IO0` 拉低。ESP 电源压降或 Wi-Fi 发射瞬间掉压时，最常见现象是反复复位、AT 无响应或 TCP 连接很快断开。

如果不是带外围电阻的转接板而是裸 ESP-12F，还要按 ESP8266 启动要求把 GPIO15 下拉；常见转接板通常已经处理，不要为了本项目随意改动其他启动脚。

## 5. 软件和阈值

### A 板

- `Dome1-A/User/main.c`：传感器采集、自动照明、LoRa 命令执行和 ACK；
- `Dome1-A/HARDWARE/ADC/bsp_adc.c`：DMA 扫描顺序固定为 `PA1` 后 `PA6`；
- `Dome1-A/HARDWARE/IO/bsp_io.c`：初始化 `PA0` PIR 和 `PB2` 继电器；
- 光照阈值 `DARK_LEVEL_THRESHOLD=1200`：当前规则是 `LIGHT < 1200` 认为暗；暗且 `PIR=1` 才开灯，否则关灯。不同光敏模块可能明暗方向相反，应先通过串口/OLED观察数值，必要时把 `<` 改为 `>` 或重新标定 1200；
- 继电器是低有效，`LIGHT=ON` 会把 A 板切到手动模式并吸合，`LIGHT=OFF` 会切到手动模式并释放；`MODE=AUTO` 恢复自动规则；
- DHT11 上电后等待约 1 秒，主循环每 2 秒更新一次。DHT11 DATA 未接或被短接时，原始示例驱动可能在等待电平处阻塞，所以接线、上拉和供电必须先确认。

### B 板

- `Dome1-B/User/main.c`：LoRa 解析、OLED、烟雾报警、ESP AP/TCP 和命令转发；
- 烟雾报警阈值 `SMOKE_ALARM_LEVEL=1800`，超过阈值蜂鸣器响并在 OLED 最后一行显示 `AL:1`；阈值需在 MQ 传感器充分预热后根据实际 ADC 值标定；
- 连续 6 秒未收到 `A,` 帧时 OLED 显示 `LORA LOST`。A 板本地自动采集/照明不依赖手机，手机断开不会停止 A 板本地循环；
- B 在每次收到完整 A 帧后发送 `B,CMD=PING`，A 用它监视网关。LoRa 连续 8 秒没有网关帧时，A 会退出手动模式、先释放继电器，再由下一次采样恢复本地 AUTO 规则；因此断开 LoRa 时不会把远程手动开灯状态永久保持。
- B 板只调用 `Beep_Init()`，不要把旧示例中的 `MYGPIO_Init()` 加回来，否则旧 LED 初始化会改写 `PB8`，影响 ESP 的 EN。

## 6. LoRa 报文和手机命令

两块 LoRa 模块须预先配置为相同的地址、信道、空中速率和串口参数；程序只使用透明传输，不在运行时改 RF 配置。串口参数为 9600、8 数据位、无校验、1 停止位。原课设调试记录中常见配置是相同地址、相同信道（例如 Addr `00`、Ch `17`），但最终以你两块模块实际配置为准。

A 板周期上报（为兼容常见 LoRa 空中帧长度，周期帧不再塞入 MODE/ALARM）：

```text
A,T=25.3,H=61.0,SMOKE=320,LIGHT=180,PIR=1,RELAY=1
```

字段依次是温度、湿度、烟雾 ADC、光照 ADC、人体状态和继电器状态。A 执行命令后的确认帧例如：

```text
A,ACK=LIGHT_ON,RELAY=1,MODE=MANUAL
```

B 发给 A 的内部命令格式为：

```text
B,CMD=MODE=AUTO
B,CMD=MODE=MANUAL
B,CMD=LIGHT=ON
B,CMD=LIGHT=OFF
B,CMD=STATUS
```

手机 TCP 工具可以发送下列任意一行（带不带结尾回车都可）：

```text
MODE=AUTO
MODE=MANUAL
LIGHT=ON        （也兼容 LIGHT_ON）
LIGHT=OFF       （也兼容 LIGHT_OFF）
STATUS
```

`STATUS` 也会转发到 A 板，由 A 立即回传一帧最新传感器数据；手机会收到 `ACK,FORWARDED,STATUS` 和随后的 `DATA`。开关/模式命令先返回 `ACK,FORWARDED`，再等待 A 的 `ACK,EXECUTED`。

手机收到的实时数据示例：

```text
DATA,T=25.3,H=61.0,SMOKE=320,LIGHT=180,PIR=1,RELAY=1,MODE=AUTO,ALARM=0
```

手机先收到 `ACK,FORWARDED,...`，A 真正执行后 B 再转发 `ACK,EXECUTED,...`。ESP 驱动的 `ESP8266_SendString()` 会自动给 TCP 数据追加回车换行，因此代码中的手机字符串故意不再手工追加 `\r\n`。

## 7. Wi-Fi 参数和手机连接

B 板启动时按以下顺序发送 AT 指令：退出回显、AP 模式、设置 AP IP、创建热点、打开多连接、开启 TCP Server。ESP-12F 常规 AT 固件默认会为 SoftAP 开启 DHCP；如果你刷的是定制固件，应按该固件手册单独打开 SoftAP DHCP。默认参数写在 `Dome1-B/User/main.c`：

| 参数 | 默认值 |
|---|---|
| 热点 SSID | `CITY_LIGHT` |
| 密码 | `12345678` |
| AP IP | `192.168.4.2` |
| TCP 端口 | `5000` |
| TCP 空闲超时 | `1800` 秒 |
| ESP 串口 | USART3，115200-8-N-1 |

手机连接 `CITY_LIGHT` 后，在 TCP 调试工具中选择“TCP 客户端”，目标地址填写 `192.168.4.2`、端口 `5000`。B 板支持 ESP 多连接模式，并从 `+IPD,<id>,...`/`<id>,CONNECT` 中记住最近的连接 ID；课堂场景建议只连接一部手机。若串口打印出的实际 IP 与默认值不同，以串口打印为准。

## 9. 推荐上电和测试顺序

1. 断电，先检查所有传感器信号不超过 3.3 V，ESP 的 3.3 V 电源和共地无误。
2. 分别烧录 A、B，再把两块 LoRa 模块的 M0/M1 置于 `0/0` 透传状态。
3. 先只给 A、B 上电，确认两块 OLED 初始化；B 串口确认 ESP AT 初始化成功。
4. 等待 MQ 和 PIR 预热，观察 A OLED 的 `S/L/P/R` 数值及 B OLED 的 `T/H/S/L/P/R/AL`。
5. 遮挡光敏传感器并触发 PIR：A 板继电器应吸合，B 板显示 `R:ON`；移开遮挡或无人后应释放。
6. 调高/模拟烟雾 AO 超过阈值：B 板蜂鸣器响、OLED 显示 `AL:1`，手机 `DATA` 显示 `ALARM=1`。
7. 手机连热点并连接 TCP `192.168.4.2:5000`，确认 `CITY_GATEWAY_READY` 和周期 `DATA`。
8. 依次发送 `LIGHT=ON`、`LIGHT=OFF`、`MODE=AUTO`、`STATUS`，检查 `FORWARDED`、`EXECUTED` 和继电器变化。
9. 断开手机：A/B 的本地 LoRa、OLED 和报警仍应继续；再断开 LoRa，约 6 秒后 B 显示 `LORA LOST`。

## 10. 常见故障排查

- **A 一上电就卡住或温湿度不更新**：先断电检查 DHT11 DATA、上拉电阻、PA12 和 GND；不要在 DATA 悬空时长时间运行。
- **光照逻辑反了**：记录明亮和遮挡时 `PA6` ADC，修改 `DARK_LEVEL_THRESHOLD` 或比较方向。
- **继电器一直吸合/一直不动**：确认模块是低有效，输入接 `PB2` 而不是 `PA2`；PA2 是 LoRa TX。开漏输入若悬空，可按继电器模块要求加上拉。
- **烟雾值乱跳**：MQ 模块先预热，确认 AO 没有 5 V；阈值 1800 只是起始值，不是通用标定值。
- **蜂鸣器逻辑相反**：本工程按 `PA12` 高电平响、低电平关编写；若你的蜂鸣器模块是低有效，只需在 B 板 `bsp_io.h` 对调 `BEEP_ON/BEEP_OFF` 宏。
- **LoRa 无数据**：检查两端 USART2 9600、PA2/PA3 交叉、M0/M1 都为 0/0，并确认两模块地址/信道/空速一致。
- **ESP 无 AT 响应或反复复位**：检查 RX/TX 是否交叉、EN 是否到 PB8、RST 是否到 PB1、IO0/IO2 是否为高、3.3 V 电源是否能承受发射峰值；不要接 5 V。代码固定按 115200 通信，若 ESP 固件曾被改成 9600，应先用串口工具恢复 `AT+UART_DEF=115200,8,1,0,0`，或同步修改 `macESP8266_USART_BAUD_RATE`。
- **手机能连热点但 TCP 连接失败**：看 B 串口打印的实际 IP，确认端口 5000；ESP-AT TCP Server 需要 `CIPMUX=1`，本工程已自动设置。如果手机没有拿到地址，检查 ESP 固件的 SoftAP DHCP 设置以及 3.3 V 供电。
- **只收到半帧 LoRa 数据**：不要把周期帧改得过长；主循环已经按 USART2 的 IDLE 帧完成标志取包，不会在 20 ms 轮询时清掉正在接收的半帧。

## 11. 本次实现的关键改动

- ADC DMA 从原示例的 `PA0/PA1` 调整为 `PA1/PA6`，避免与 PIR 的 `PA0` 冲突；
- A 板加入 DHT11、烟雾、光照、PIR、继电器统一采集/控制；
- B 板加入 OLED 环境/通信/继电器/报警显示和蜂鸣器；
- B 板切换到 AP + TCP Server 专用 ESP 驱动，USART3 使用 `PB10/PB11`，EN/RST 使用 `PB8/PB1`；
- 修正旧示例中 USART3 所有权、LoRa 报文字段解析、ESP 接收缓存和半帧清除问题；
- 周期 LoRa 帧控制在常见空中帧长度内，命令执行结果用独立 ACK 返回；
- A、B 的 Keil 工程和生成 HEX 均保留在本目录，原始课设目录未被覆盖。
